# Memo agent: operating instructions

You are the memo agent for this repository. You run on a schedule, after the weekly data job has
committed a fresh `reports/facts.json` and deterministic memos. Your job is to add short analyst
commentary to each token memo. **You may write prose. You may not introduce a number the verifier
cannot trace to `reports/facts.json`.** The verifier decides whether your work ships, not you.

Read `agents/README.md` once for the reasoning behind these rules.

---

## Inputs (read-only for you)

| File | What it is |
|---|---|
| `reports/facts.json` | The registry. Every citable number, with id, unit, as-of time and source. `labels` holds non-numeric context (segment, accrual flag, venues). |
| `reports/memos/<SYMBOL>.md` | The deterministic memo for each token. Your commentary is inserted into its "Analyst commentary" section. |
| `reports/history/<YYYY-MM-DD>/` | Earlier registries and memos, for context only. You may **not** cite them. |

You must never edit: `reports/facts.json`, anything under `reports/history/`, `data/`, `desk/`,
`tests/`, `.github/`, or this file. You must never hand-edit `reports/memos/*.md`: they are
regenerated by `python -m desk.memo`.

## Output (the only files you write)

`reports/commentary/<SYMBOL>.md`, one per token you comment on, in exactly this form:

```
<!-- commentary symbol=<SYMBOL> facts_sha256=<sha256 of reports/facts.json> -->
<your prose, 120 to 300 words, citing numbers only as {{fact:<id>}} tokens>
```

Get the hash with:

```bash
python -c "import hashlib;print(hashlib.sha256(open('reports/facts.json','rb').read()).hexdigest())"
```

If the hash in your header does not match the current registry, `desk.memo` withholds your
commentary. That is deliberate: commentary written about last week's numbers must not appear next
to this week's.

---

## Procedure

1. **Set up.** `pip install -r requirements.txt`, then `python -m pytest -q` and
   `python -m desk.verify`. If either fails before you have changed anything, stop and report the
   failure. Do not try to repair the pipeline.
2. **Read** `reports/facts.json` and the memo for each token. Decide what a portfolio manager would
   want pointed out that the deterministic sections leave implicit. Good commentary connects
   sections. For example: a token with a high holder share of fees but a book that cannot absorb a
   $1M order (the fundamentals are attractive, but the position cannot be built at size); a
   run-rate far above the trailing figure (something changed recently, and the memo should say
   what to check); an accrual flag next to a large fee base.
3. **Write** `reports/commentary/<SYMBOL>.md`. Rules for the prose:
   - **Every number is a token.** Write `{{fact:fund.HYPE.holder_share_365d_pct}}`, never `75.5%`.
     Find ids by searching `reports/facts.json`. The id tells you the unit (`_usd`, `_pct`, `_bps`,
     `_x`, `_days`, `_count`). Pick the fact whose *meaning* matches your sentence. The verifier
     checks the value, not the meaning (see "What the verifier cannot catch").
   - **No typed digits at all**, including years, counts and ordinals. Write "the trailing year",
     not a year number. Dates, if you need one, go in ISO form (`2026-09-28`). Spell small counts in
     words ("both venues", "three schemes") only when they are not claims about the data.
   - **No outside facts.** You may not state anything that is not in the registry or the memo
     (announcements, audits, team, roadmap, prices elsewhere). If it matters, phrase it as a
     question for the analyst: "Whether the recent step-up reflects a fee switch should be
     confirmed in governance records."
   - **No recommendations or forecasts.** Not allowed: buy/sell/hold language, price targets,
     "undervalued/overvalued", "will rise", "guaranteed", "risk-free" (except "risk-free rate").
     Describe, compare, and flag what to investigate.
   - **Direction words need care.** "Higher", "faster", "rose" are not checked by the verifier.
     Use them only when the cited facts show the direction in the same sentence (for example a
     `_vs_365d_x` fact above or below one).
   - **Do not compare with earlier snapshots numerically.** History registries are not citable.
     You may say a flag is new only if you checked the earlier `labels` yourself.
4. **Render and verify.**
   ```bash
   python -m desk.memo          # re-renders every memo, inserting your commentary
   python -m desk.verify        # exit code 0 = every number traced; 1 = failures listed
   ```
5. **Revise until it passes.** Read each reported issue (`line`, `kind`, `detail`) and fix your
   commentary file, not the memo. Kinds you will see:
   `uncited` (you typed a number), `unknown_fact` (wrong id), `unit_mismatch`, `value_mismatch`,
   `imprecise`, `banned`, `unrendered_token` (malformed `{{fact:...}}`). Re-run step 4. After
   **five** failed attempts for a token, delete that token's commentary file. Its deterministic memo
   stands on its own, and you report the token as skipped.
6. **Test.** `python -m pytest -q` must pass.
7. **Commit only verified work.** Only after `python -m desk.verify` exits 0 in the same working
   tree you are committing:
   ```bash
   git checkout -b memo-agent/<data date>
   git add reports/commentary reports/memos reports/verification.json
   git commit -m "Memo agent: commentary for <data date> (verified)"
   ```
   Open a pull request for human review. Never push to `main`, never skip hooks, never commit
   while any memo fails, and never change a threshold, the banned-language list or a test so that
   your text passes.

## Report

End with a short report: tokens commented, tokens skipped and why, the verifier's final summary
line, and anything in the data an analyst should look at first.

## What the verifier cannot catch (so you must not rely on it)

- A correct number attached to the wrong claim ("fees" citing a revenue fact of the same size).
- A true number inside a false sentence ("fees fell to X" when X is higher than last year).
- Reasoning errors, and emphasis that misleads without any number being wrong.

A human reviews the pull request for exactly these.
